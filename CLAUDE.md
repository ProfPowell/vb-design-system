# Claude Instructions — @profpowell/vb-design-system

Design-system documentation Web Components (19 of them) decomposed out of
Vanilla Breeze (VB) core in 0.3.0. Token-driven, light-DOM, no build-time
coupling to VB. Published to npm; docs on GitHub Pages.

## Layout

| Path | Owns |
|------|------|
| `src/web-components/<name>/` | One component: `logic.js` (class extends `VBElement`), `styles.css` (light DOM), `api.json` (manifest, feeds `site/data/apiRegistry.js`), `static.html` (no-JS fallback) |
| `src/lib/` | Shared code: `vb-element.js` (base class, **mirror of VB core** — keep byte-identical), `bundle-registry.js`, `color-utils.js` |
| `src/patterns/` | CSS-only authoring patterns (`do-dont`, `token-table`) |
| `src/index.js` / `src/index.css` | Barrels. Every new component must be added to both, and to `exports` in `package.json` |
| `dist/` | esbuild output. **Committed** — CI fails if it is stale. Run `npm run build` after any `src/` change |
| `site/` | CookSSG docs site (own `package.json`). `scripts/copy-assets.js` vendors VB + this pack into `src/pages/assets` (gitignored) |
| `docs/` | **Published Pages output**, generated by `site/scripts/publish-docs.js`. Never hand-edit |
| `tests/components/` | Playwright specs. They run against `docs/` via `tests/serve-docs.mjs`, so rebuild + republish before testing a change |

## Commands

```bash
npm run build                 # dist/ (esm + min, js + css)
npm run test:components       # Playwright, serves docs/ on :4330
cd site && npm run build      # copy-assets + cook build -> site/dist/pages
cd site && node scripts/publish-docs.js /vb-design-system   # -> docs/ (+ pagefind index)
```

Full change loop for a component: edit `src/` → `npm run build` → `cd site && npm run build && node scripts/publish-docs.js /vb-design-system` → `npm run test:components` → commit `src/`, `dist/`, `docs/` together.

## Conventions

- Components extend `VBElement`: implement `setup()` / `teardown()`, not `connectedCallback`. `setup()` re-runs on every reconnect (base class clears `data-upgraded` on disconnect) so it must be idempotent: use `replaceChildren`, `innerHTML =`, or a `node?.parentNode === this` guard before appending owned DOM.
- Light DOM only, styled by `styles.css` against VB tokens (`--color-*`, `--size-*`, `--font-*`, `--ease-*`). Always provide fallbacks (`var(--size-s, 0.75rem)`).
- Use VB layout primitives (`[data-layout=stack|grid|cluster]`, `layout-grid`, `layout-card`) instead of local flow-spacing CSS.
- Icons via the `[data-icon]` primitive; `<icon-wc>`, `<brand-mark>`, `<color-picker>`, `<drag-surface>`, `<theme-picker>` stay in VB core and are runtime peers, not bundled.
- Every component ships with a doc page in `site/src/pages/elements/<name>.html` (`<browser-window>` + `<code-block>` demos), an `api.json`, and a Playwright spec. Never defer the doc page.
- Doc pages and demos: semantic elements or VB custom elements, no bare `<div>`.
- Root-absolute URLs in site pages (`/elements/...`, `/cdn/...`) are prefixed with the Pages base at publish time. Do not hardcode `/vb-design-system/`.

## Shared with VB core (keep in sync)

These files are copies of VB core and must not drift. Diff against `~/src/vanilla-breeze` when bumping VB:

- `src/lib/vb-element.js` ← `src/lib/vb-element.js`
- `src/web-components/theme-import/dtcg-deserialize.js`, `theme-export/dtcg-serialize.js`, `theme-export/theme-css-parse.js` ← `src/lib/dtcg/`
- `src/web-components/theme-import/catalog/` ← `src/data/theme-catalog/`

`site/scripts/port-from-vb.js` ports doc pages + demos from the VB repo.

## Release

1. Bump `version` in `package.json`, `npm run build`, run tests, commit.
2. `npm publish` (`prepublishOnly` rebuilds dist). Tag `vX.Y.Z` on that commit.
3. Republish docs if anything user-visible changed.

## Working style

- Small focused commits, conventional-commit format, scope `ds` or the component name.
- Prefer platform-native solutions over packages. Ask before expanding scope.
- If something is ambiguous, make the best call and note the decision in the commit message.
